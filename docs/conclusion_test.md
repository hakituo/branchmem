# 测试集结论（test-v1）

数据：`results/test-v1`（20 个场景、69 道题，其中 34 道 leak 题，3 次运行，`deepseek-v4-flash`，温度 0，commit `d6b4c56`，场景集 `76614b0ba417`）。完整表格见 [results_test.md](results_test.md)，由 `python -m branchbench answer-report results/test-v1 --markdown docs/results_test.md` 生成。下面的数字都是 3 次运行的均值。

**泄漏很普遍。** 用中性提示词时，四个现有做法在 leak 题上的泄漏率是：整段摘要 40.2%，Mem0 + 原文按分支过滤 50.0%，全量历史 52.0%，Mem0 开源版 60.8%。按来源判断可见性（branchmem）和"只给当前分支原文"的上界都是 5.9%。大部分泄漏属于"答对了但顺带提到兄弟分支的说法"，比如"你现在预算 4000，之前也提过 3000 和 10000"。直接答成兄弟分支说法的只占 3–10%。四个基线的正确率在 70–80%，branchmem 是 95.7%。所有系统的保留题命中率都是 100%，说明按分支过滤没有把该留的信息挡掉。

**泄漏最多的分叉方式是切回旧分支（`switch_back`）。** 四个基线在这里的泄漏率是 79–96%，branchmem 是 12.5%。模型一般不把两个分支的说法当成冲突，而是把它们并在一起，例如"你对花生和虾都过敏"。其余几种分叉方式，基线的泄漏率是：编辑用户消息 29–58%，重新生成 40–67%，从检查点分叉 19–38%，分支内改口 22–56%。

**只过滤原文挡不住多少。** Mem0 把原文换成只含当前分支的版本后，泄漏率从 60.8% 降到 50.0%，只挡住 18%。原因是兄弟分支的事实已经写进了 Mem0 自己的记忆条目，原文过滤管不到这些条目。作为对照，同样的原文过滤用在全量历史上（也就是上界），泄漏率从 52.0% 降到 5.9%，挡住 89%。

**稳健性检查：冲突处理提示词。** 这条提示词是事先写定的，没有调过参。它要求模型以当前对话为准、只给一个答案。用它之后基线的泄漏率降到 21–42%，正确率升到 75–88%，但泄漏没有消失。其中切回旧分支的泄漏率仍有 46–83%，而且"答成兄弟分支说法"的比例变高了：全量历史从 2.9% 升到 13.7%，Mem0 从 9.8% 升到 18.6%。也就是说，模型更常只挑一个答案，但挑错的次数也多了。branchmem 在两种提示词下都是 5.9%。

**测量上的问题。** 测试集跑完后发现，有 2 道 leak 题（s006 q2、s024 q2）的禁止词就出现在问题里，正确的否定回答也会被判成泄漏。这 2 道题在所有系统上几乎都被判泄漏（35/36 和 36/36），上界的 5.9% 就是这么来的。测试集已经冻结，题目没有改。报告里另附一张去掉这 2 道题的敏感性分析表：branchmem 和上界降到 0–1%，基线降了 2–4 个百分点，结论不变。

**其他局限。** 场景是合成的中文对话，leak 题只有 34 道，只用了一个回答模型，评分只看关键词。各分叉方式只有 5–8 道 leak 题，单个格子的数字波动很大。
